# 审校交接协议

首次独立审校、修订复核、收到过期报告或处理分歧时读本文件。报告是可追溯判断，不是自动改变公共稿状态的指令。`project.py` 不读报告；整合者须核真实输入和处置结果。

## 报告合同

报告保持 Markdown。采用以下结构；填写真实路径与指纹，不复制示例值冒充结果。`original_sha256` 按工作包 `original` 原字串的 UTF-8 字节计算，不另加换行。文件指纹按实际文件字节计算。

```markdown
# I.1 / fw-i1-004-01 审校报告

## 输入
- role: ai_review / human_review / self_check（只选实际类别）
- executor: 本次实际执行者；AI 不填造出的姓名
- workpack: 路径；sha256: 实际值
- draft: 路径；sha256: 实际值；revision_round: 0 / 1 / 2
- original_sha256: 实际值
- source_id / locator: 本次见证来源与完整坐标

## 范围与查阅
- 已核：原文／译文／具体注释 ID 及坐标
- 未核：缺少资料或未获分配范围
- 实际查阅：来源 ID、具体页面或定位、查阅限度

## 问题
### R-01
- 词目／位置：原文词句、译稿字段、注释 ID
- 类别：底本／漏误译／无据增补／出处／声形／中文／术语
- 问题：具体缺陷；解释分歧写明可成立读法
- 依据：原文或实际核过的来源与定位
- 建议：必要改句或应补证据
- disposition_required: fix / qualify / decide / optional
- blocks_integration: true / false；说明影响

## 结论
- 当前版本：ready / needs_revision / blocked / partial_review
- 未决项：问题编号、影响范围、下一步
```

没有问题时写「本次已核范围未见须改问题」，不保留空 R-01。`ready` 只针对所核版本和范围；`partial_review` 不能转写成全段通过。报告署名可以记录实际 AI 角色与执行记录，不能写虚构学者或冒称人类核阅。

三轮报告复用上面结构，分别绑定实际输入：`<id>.r0.md` 核 `reports/drafts/<id>.json`，`revision_round: 0`；`.r1.md` 核 `reports/revisions/<id>.r1.json`，轮次为 1；`.r2.md` 核 `.r2.json`，轮次为 2。r2 复核不授权第三轮修订。问题编号延续前轮；新增问题另编号，已解决项写解决依据，不删原问题。

逐项处置也可复制以下结构到指定交接说明，每个问题写一项：

```markdown
### R-01 处置
- 结论：采用／未采用／补证后采用／延期（选实际结果）
- 理由与依据：具体读法、已核资料或保留分歧的理由
- 修改范围：translation／具体 note ID／无正文改动
- 当前稿：实际路径与 SHA256
- 复核：需要核哪处；已核时指向绑定此稿的报告
```

## 问题如何分级

**阻断项：** 原文范围或版本未核，漏掉一句／否定／主要动作，偷换主客或人物关系，注释引用捏造来源，当前稿仍断言无据词源，或者交稿同字段冲突未决。写出具体错误和所需修正；不能只说「不够好」。

**可降级项：** 语音、词源或典故暂无法坐实，但已有不依赖该猜测的完整译文。把断言改为 `proposal` 或 `uncertain`，说明查阅限度与译法损失后，可留待研究。证据强度与公共段落状态分别判断。

**选择项：** 两条读法均有上下文或资料支持。比较各自保留与损失，建议正文采用一路、注释存另一路；不能把不同学说机械并列为都已证实，也不能为统一而抹掉分歧。

**偏好项：** 不改变语义、声形、语域或可读性的同义替换。列为 `optional`；不能用它阻断交稿或启动新一轮全段重译。中文生硬若妨碍理解则写清对应句法，别降成纯偏好。

## 逐项处置与两轮收敛

译者或整合者在获分配的交接说明记录「问题编号／采用或未采用／理由或证据／变更字段／新稿路径」。不改审校者输入和原报告。每次修订给出完整可解析段落对象，保留最初 `draft`，把当前采用文放 `translation`；修订到哪版就报哪版。

一轮指针对同一审校意见集合完成一次定点修改与交付，不按修改字符数算。初译后的修订总数至多两轮；换人、超时重试或换报告名不重置次数。第一轮处理明确错误和必要补证，第二轮只处理仍存实质问题与修订引入的回归。已解决问题不因更喜欢另一种措辞重新打开。

第二轮后有三种结果：实质错误仍在，保留 `blocked`；正文完整、只余已标明解释分歧，列限度后收口；只余措辞偏好，结束。轮次上限限制无休止打磨，不保证稿件合格。用户以后提出新证据或不同范围，可建立新修订任务，沿用旧问题与证据；不能靠新任务编号把旧漏译当成已完成。

## 输入变化与迟到报告

收到报告先核实际稿文件 SHA256，不能只看 `baseline.manuscript`。例如审校开始时译稿为 v1，译者另交 v2；晚到 v1 报告即使写 `ready`，也只归 v1。整合者比对 v1/v2，把变更处、受影响注释和上下文交复核；未核 v2 前不计 v2 通过。

原报告已完整核过全段、新稿只改一条注释时，可以沿用未改部分结论，并明确「旧报告覆盖未改部分，本次只复核 n-…」。新的总体验收记录须同时指向旧报告、新稿及实际差异，不能悄悄把旧 SHA256 换成新值。来源新增但与本段无关时，只记差异；本段依据改变则重核具体主张。

若报告与输入不符、未核范围写成全审或声称读过打不开的资料，退回说明缺口；不要原样反复重试。瞬时工具失败才按 [冻结与恢复](../../translate-chapter/references/packets-and-recovery.md) 接续。审校失败不能复制初译冒充通过。

## 交回整合者

报告交付后，整合者核问题处置、来源登记、当前稿与所审版本，再决定是否合入。审校者不推进断点。自动检查能发现字段或链接问题，不能验证声形判断、来源支持范围或全章连续覆盖。

人工完成审校还须有真实姓名或公开账号，以及实际核阅范围；AI 分析或代理名不填公共 `reviewers`。原稿已有人工审校而本轮改变译义或注释时，当前稿退为 `revised` 并清空当前审校署名；既往记录留在版本历史，不删除事实。
