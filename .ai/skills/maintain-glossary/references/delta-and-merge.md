# 术语增量、变体与合并

首次维护、收到旧基线候选或修改适用范围时读本文件。本协议用现有 JSON 字段交接；没有配套自动合并器，`project.py` 也不读取增量。最终回写由整合者逐项核验。

## 正式条目与工作字段

`glossary/terms.json` 是条目数组。当前条目含 `term`、`translation`、`status`、`note`、`source_ids`；已有 `status: provisional` 不能因本轮查到资料便擅改成新状态名。`term` 没有独立 ID，本轮以原样词形定位；若同名出现两条，先辨析，不能任选一条覆盖。

公共条目不新增 `scope`、`variants` 或证据对象。需要长期保留的范围与存疑说明写入 `note`；各次出现位置、候选关系和受影响段落保留在增量。字段扩展须另改格式与校验器，不能靠当前校验器忽略未知字段便称已经支持。

## 可复制的增量结构

以下示例取现有 HCE 条目，只演示如何加明确范围，不表示新增文献判断或已经获准合入。基线 SHA256 须换成实际值；`before` 也须从本次所读表原样复制。`after` 可直接作为现有格式的候选条目，不能把整个增量对象塞入总表。

```json
{
  "schema_version": 1,
  "batch_id": "I-1-fw-i1-003-01",
  "baseline": {
    "glossary": {"path": "glossary/terms.json", "sha256": "<实际指纹>"}
  },
  "operations": [
    {
      "action": "update",
      "term": "HCE",
      "before": {
        "term": "HCE",
        "translation": "HCE（保留字母）",
        "status": "provisional",
        "note": "须逐处记录变体，不将所有 HCE 都补作同一人名。开篇 Howth Castle and Environs 已见此字母组。",
        "source_ids": ["joyce-fp", "fw-howth"]
      },
      "after": {
        "term": "HCE",
        "translation": "HCE（保留字母）",
        "status": "provisional",
        "note": "本条约定字母组处理，不裁定人物身份。003.01–003.03 的 Howth Castle and Environs 可核首字母；其他变体逐处判断。",
        "source_ids": ["joyce-fp", "fw-howth"]
      },
      "reason": "把形式约定与身份判断分开，保留暂定状态。",
      "scope": {
        "segment_ids": ["fw-i1-003-01"],
        "surface_forms": ["Howth Castle and Environs"],
        "limit": "此处只核字母形式，不从本条推定其他出现处同一人物。"
      },
      "evidence": [
        {"source_id": "joyce-fp", "locator": "003.01–003.03", "supports": "原文词形与首字母；不独立证明人物身份。"}
      ],
      "affected_segments": ["fw-i1-003-01"]
    }
  ],
  "unresolved": []
}
```

`add` 用 `before: null`，`after` 仍含全部正式字段。`update` 的 `before` 须完整，不只写旧译名。`action` 不含删除；确需删重复或改词形，另列建议、引用位置和链接影响，交整合者处理。每项写理由、证据支持范围、适用段落及需复核的旧段。新增来源另交登记建议；未登记时标依赖，不借旧 ID 掩盖缺口。

证据尚未核实的候选留在 `unresolved`，说明需要哪份资料及正文能否用保守译法继续。工作包原文可以支持词形观察，不能自动支持历史背景、标准发音或作者用意。

## 变体与语境

先记实际 `surface_forms`，再判断是否同一形式家族、同一所指或只是音近。HCE 的字母模式、一个具体人名和某处称谓并非同一层判断。大小写、错拼与音变不自动归并；输入可能同形异义时，在 `note` 写清本条约束，不用全书同词替换压平差别。

本批清单 `<batch-id>.terms.md` 按「词形 → 采用译法 → 适用位置与限制 → 依据 → 本批动作」写。须带足理由与存疑处，让译者无需读全表也能判断；不能把有争议的 `note` 称为不可核疑的权威。反例也要具体：Howth 暂用「霍斯」不表示其标准读音已核，更不能据此给所有含近似音节的混合词硬套地名。

正文保留原词、造词或按局部语境异译时，写明与旧约定的关系，不悄悄建立第二套全书定译。只在一处成立的例外写入该段注释及清单；确需跨段沿用才形成总表更新。

## 三方合并

整合者合入前读最新总表，逐操作比较 `before`、当前条目与 `after`：

1. 当前等于 `before`，可核来源后采用 `after`；当前已经等于 `after`，记为已应用，不重复新增。
2. 只有当前改过的字段，保留当前值；只有候选改过的字段，可采用候选值。未改字段和其他条目原样保留。
3. 两边改同字段且新值不同，挂起该条，列三方值与证据。`note` 两边都改也属冲突，不能把互相矛盾的句子拼起来。`source_ids` 不默认取并集；各来源须支持最终主张。
4. `add` 遇到当前同名项，不再追加。内容相同便记已存在；内容不同则核范围与证据，再决定改既有项还是继续存疑。

例如任务 A、B 都据同一旧表派出：A 要改 Howth，B 只新增另一条。A 合入后，B 仍可把新条增量合入，并保留 A 的 Howth 与其他条目。B 若也改 Howth 的 `note`，只挂起该条；B 其他互不相关的操作仍可交整合者核验。不能因整表 SHA256 改变而把所有候选重做，也不能更新指纹后直接覆盖。

回写只发生在单一整合者控制的步骤。写前再确认所读公共表未变；无法排除并发覆盖时先留候选，不写总表。解析失败或条目减少，先保留错误现场与候选，查差异；不能用旧基线或其他卷副本覆盖恢复。重试只用于瞬时工具错误，不用来绕过冲突。

## 核验与交回

合入后重读文件，核条目数等于原数加实际新增，旧条目集合仍在，未改字段未变，重复词形已处理，来源 ID 可解析。逐条比较比单看数量更重要；等量覆盖仍会丢记录。格式检查不证明来源支持译名，须保留证据与范围判断。

术语更新只完成总表阶段。列 `affected_segments`，由整合者派已用段落复核，必要时交 [review-translation](../../review-translation/SKILL.md)；不要声称正文已统一。AI 改词不会自动获得人工审校署名。交回时说明哪些操作已合入、哪些因依赖或同字段冲突暂存，以及下一位执行者实际需要读的文件。
