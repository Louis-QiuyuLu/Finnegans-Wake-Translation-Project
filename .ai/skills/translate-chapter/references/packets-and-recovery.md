# 工作包、冻结与恢复

在制作交接包、恢复中断、收到迟到交稿或合入冲突时读本文件。这里约定工作文件；`scripts/project.py` 目前不执行任务调度，也不验证这些报告。整合者须实际比对，不把人工协议说成已有后台能力。

## 小包与版本

每段 `reports/workpacks/<id>.json` 沿用 `templates/workpack.json`。除原文与坐标外，保留实际 `source_checks`、问题、相关术语、前段 ID 和下一锚句。`schema_version: 1` 表示包格式；`baseline.manuscript`、`baseline.sources`、`baseline.glossary` 各记录 `path` 与 `sha256`。指纹仅识别读过哪一版，不能证明版本正确、来源真实或译义可靠。

工作包达到 `prepared` 后冻结，不在包里更新交接阶段。发现见证差异，另交更正建议；整合者核查后发新文件，如 `reports/workpacks/<id>.v2.json`，保留旧包。批次记录改指实际版本路径与指纹，再核受影响范围。分配审校前另算实际包与交稿文件 SHA256；同名文件内容变化须查清，不能冒充冻结输入。

相邻原文只取理解边界所需范围；前文摘要通常数百字，注明段 ID。术语只列本批词形、译法、适用范围、来源和存疑处。跨作品研究只带有关条目和证据定位，不夹整部书缓存、全库注释或冗长搜索日志。包不够时定点补充；不为追求小包切掉未完句或关键反证。

## 手工工作记录

整合者用 `reports/batches/<batch-id>.json` 保存一批，沿用 `templates/batch.json`；已有等效记录可兼容转入，不另造平行账本。`batch-id` 用章文件名加首段 ID，例如 `I-1-fw-i1-003-04`。这是**手工维护的交接记录**，不是 `project.py` 读取的执行状态机。下例展示已落初译的阶段；指纹须填实际值，不能照抄占位：

```json
{
  "schema_version": 1,
  "batch_id": "I-1-fw-i1-003-04",
  "chapter": "I.1",
  "segment_ids": ["fw-i1-003-04"],
  "segments": {
    "fw-i1-003-04": {
      "stage": "drafted",
      "workpack": {"path": "reports/workpacks/fw-i1-003-04.json", "sha256": "<实际指纹>"},
      "draft": {"path": "reports/drafts/fw-i1-003-04.json", "sha256": "<实际指纹>"},
      "review": null,
      "revisions": [],
      "revision_round": 0,
      "attempts": [],
      "integration": {"state": "not_integrated", "fields": [], "unresolved": []}
    }
  },
  "publication": {"state": "not_published", "commit": null, "url": null, "checked_at": null}
}
```

公共基线留在冻结工作包；批次记录指向实际版本，不手抄三套基线。多段批次在每段记录各自包路径与指纹，不能用一个段包代表整批。`attempts` 只写真实启动、失败原因与可用成果。持久阶段取 `preparing`、`prepared`、`drafted`、`pending_review`、`needs_revision`、`ready_to_integrate`、`integrated` 或 `blocked`；架构文档中的 `source_ready` 等只是验收关口标签。发布另记 `publication.state` 为 `not_published/pushed/deploying/published/failed`，不改译稿阶段。记录缺失时从文件与公共稿重建，不能据文件名猜阶段。

`draft` 保留初译路径与指纹，修订按轮次放入 `revisions[]`，每项记 `round/path/sha256`。当前稿是最后一份完整修订；无修订时才是初译。`review` 指当前收到的报告及所核版本，至少记 `path/sha256/input_draft_sha256`；尚未核当前稿便保留 `pending_review`，不能因旧报告存在就改为可合入。

## 同段冻结

同一段按「包 → 初译 → 审校 → 定点修订 → 复核」衔接。审校读取哪个文件，派工便锁定哪个输入版本。译者若需边审边试改，另存候选文件，不能覆盖审校输入。迟到报告仍归原版本；新稿与旧稿只差一个字，也先看该字是否影响原结论。

输入改动后按影响处理：

- 原文、页行、见证来源或主要句法变化：重核受影响译句和注释；原审校不再给这些部分背书。
- 译文或译注变化：对照修改处及上下文复核，明确范围；不能把局部复核写成全文重审。
- 来源表只新增无关条目、术语表只改无关词：记录基线差异，不要求整段重译。
- 本段所用来源撤回或术语理由变化：追到具体主张，决定重审、降级或保持；不能只更新指纹后继续。

## 失败与重试

先分清工具失败、交稿不完整、证据不足和版本冲突。超时或工具报错后，查指定输出是否完整落盘。完整包括 JSON 可解析、ID/范围/原文与工作包一致、必需字段齐备；审校报告还须绑定实际输入并覆盖指定范围。不能只查文件存在或非空。

瞬时工具失败可对同一角色同一版本重试至多两次，合计至多三次启动。每次先排除旧任务仍在写同一输出；重试接续已有可用内容，不删已核成果。证据不足、包字段有误或语义冲突不靠原样重试解决，转具体补证或整合判断。工具并发不足时串行等待，不绕过限制。

重试用尽便保存阶段、失败原因、输入与交稿路径。没有独立审校，保留 `pending_review`；缺原文或漏译，保留 `blocked`。不得跳过该段，把后段算作连续完成；也不得把初译复制成审校稿来填目录。角色退回或执行者更换不重置已用修订轮次。

## 恢复判定

1. 重读公共章稿与主断点，核下一坐标、原文锚句及连续范围。工作记录和断点不一致时，按已核正文重建差异，不能任选较远进度。
2. 比对工作包、交稿与报告指纹。包有效且完整初译已落盘、尚未合入时，复用初译接审校；不要重译。报告只核旧稿则留作历史，给当前稿补受影响复核。
3. 公共章稿已有同 ID 时，判断是否已合入；内容相同便不再插段。ID 同而原文或坐标不同，停下查版本，不另造 ID 逃过重复检查。
4. 输入变化时按影响筛选，只恢复缺失阶段，保留可用研究、初译和问题处置；摘要不能覆盖实际稿件。
5. 只有整合者更新主断点。未完整合入的自然段，断点仍停在段首。更远处样稿和研究不填补中间缺口。

## 三方合并与完成

把派工基线、当前公共稿、交稿逐字段比较。仅交稿改过而公共稿未改的字段可合；公共稿独有变化原样保留；两边改同字段便列冲突及依据。来源表和术语表按 ID 或精确词条增量合并，不把旧全表拷回去。受影响字段未处理，不能标本段 `ready_to_integrate`。

合入后核段落顺序、范围、原文、注释来源与真实状态。词源存疑可用 `uncertain` 保存，前提是正文完整且不靠该猜测才能成立。漏译、未核原文、假来源和同字段冲突仍阻断推进。由 [checkpoint](../../checkpoint/SKILL.md) 保存下一锚句、生成便读稿；检查命令通过不能代替全章覆盖核对。

现有断点格式有两处兼容限制，详见 `docs/SKILLS_ARCHITECTURE.md`：当前 IV 章已有 628.15–628.16 远段样稿，校验器却按该章最后一段判断下一坐标；进入 IV 顺序翻译前，须先扩工具区分连续前缀与样稿，不能取较大坐标跳过中间正文。格式另要求有效 `next` 与非空 `next_original`，没有全书终点状态；到真实末段前，须先扩格式和校验器，再写终点。不能伪造下一句或用回环开篇冒充未译锚句。本技能说明限制，不宣称已经实现这些支持。
